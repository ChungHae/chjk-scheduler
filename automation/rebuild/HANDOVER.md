## 6-1. 업체 지점(서울/화성) 구분 + 종사업장번호 [r158~r165 완료, 배포됨]
- 사용자 선택: ③안 = 같은 업체명으로 지점만 다른 2줄 등록 허용. 식별자를 "업체명"에서 "업체명+지점"으로 변경.
  이유: 향후 ERP 확장 시 지점 구분값이 있어야 편함.
- 기존 업체 분류 규칙(사용자 지정): clientInfo 메모에 "화성" 포함 = 화성지점, 나머지 = 서울지점.
  이 일괄 분류는 일회성 — 후보가 0곳이 되면 버튼·패널이 자동으로 사라진다(별도 플래그 없음).
- fxAlias/fxTerms/fxOpenings 는 이미 "사업장|이름" 키라 미수 원장은 사업장별로 자동 분리됨.
- 1단계 r158(자료 구조): clientList = [이름, 번호, 지점, 종사업장번호].
  ※ clientList 를 새로 건드리는 코드는 반드시 _cliMake/_cliKeep 을 쓸 것.
    배열 리터럴 [nm,bz] 로 넣으면 지점·종사업장이 조용히 사라진다.
- 2단계 r159(폼 입력칸·목록 지점열·필터). 종사업장번호는 필수 아님(사용자 지시) — 검증 걸지 말 것.
- 2b r160(메모 기준 일괄 분류, 일회성·자동소멸).
  ※ 정식 배포 후 정식에서 1회 실행 대상. 코드까지 걷어내려면 _clxMig* / _clxMemoHi / clxMigWrap 제거.
- 3단계-A r161(clientInfo 키 이관).
  ※ 업체 상세는 clientInfo["이름|지점"]. 새 코드는 _clxInfo(행) / _clxInfoKey(이름) 을 쓸 것.
    clientInfo[이름] 직접 접근 금지. 삭제 시에는 clientList 에서 지우기 전에 키를 먼저 확정할 것.
    _fxCeoMap 색인의 값은 업체명이어야 함(복합키로 바꾸면 미배정 대량 발생).
- 3단계-B r162: 업체 식별자는 이제 "이름|지점".
  ※ _clxExp 와 #clxForm[data-orig] 는 복합키다. 업체명이 필요하면 _ciSplit(key).name 을 쓸 것.
    이름만 받는 옛 경로(deleteClient/qVendorDel)는 같은 이름이 2곳 이상이면 목록을 건드리지 않는다.
- 4단계 r163: 계산서 레코드에 vsb(거래처 종사업장번호) 저장. 채우기 도구는 후보 소진 시 자동 소멸.
  ※ 재적재(홈택스 재업로드) 후 업체 페이지에서 "종사업장번호 채우기" 를 한 번 돌리면 일괄 반영됨.
  ※ 사업자번호 하나에 종사업장이 여러 곳인 거래처(플라즈맵: 본점+4곳)는 실제로 존재.
    결제는 본사 일괄이라 미수 원장은 사업자번호 단위로 합치는 게 맞다(사용자 확인, 2026-08-26).
    이런 업체는 r164 부터 자동 채우기 대상이 아니며 업체 화면의 칩에서 사람이 직접 고른다.
- 배포 전 전수 점검에서 잡은 것(r165): 업체 엑셀 가져오기가 같은 이름 2줄을 이름만으로 찾아 뒤 행이 앞 행을 덮었다.
  ※ 이제 가져오기는 (사업자번호|이름)+지점 으로 대상 줄을 찾는다. 지점 칸이 빈 구버전 엑셀은 후보가 하나일 때만 갱신하고,
    같은 업체가 서울·화성 양쪽에 있으면 그 행을 건너뛰고 안내한다 — 사용자에게 '엑셀의 지점 열을 채워 다시 올리라'고 안내됨.
- 남은 단계(선택):
  5(선택)=견적 거래처(quoteVendors)에 지점 부여 — 지금은 이름 기준이라 같은 이름 2줄이면 원장이 하나로 공유됨,
  6(선택)=매입매출 _findClientByBiz 3곳 지점 인식.

## 6-2. 향후: 세금계산서 발행 대비 — 업체 아래 "사업장 목록" (2026-08-26 논의, 지금은 보류)

사용자 의도: 현재 시스템이 ERP로 발전해 계산서 발행까지 가능해질 때를 대비해 종사업장번호를 물음.

현재 구조로 발행이 가능한가 — 항목별 점검:
  공유(지금 구조로 충분): 사업자등록번호, 상호, 대표자명, 업태, 종목
  사업장마다 달라지는데 지금은 한 칸씩뿐:
    - 종사업장번호  -> clientList c[3] 한 칸
    - 사업장 주소   -> clientInfo.zip/addr/addr2 한 칸
    - 계산서 이메일 -> clientInfo.taxEmail 한 칸
    - 담당자        -> clientInfo.contacts 목록은 있으나 사업장 구분 없음
  => 플라즈맵(본점+종사업장4)에 오송공장으로 발행하려면 오송의 주소·이메일이 필요한데 담을 곳이 없다.
     발행 기능이 붙으면 이 구조로는 안 된다.

지금 보류해도 되는 이유(중요):
  r163 부터 계산서 레코드마다 vsb(거래처 종사업장번호)를 저장한다. 재적재하면 과거 계산서까지 들어온다.
  즉 "이 거래처에 어느 사업장으로 발행해왔나" 는 이력에서 뽑을 수 있다(_fxVsbList 가 이미 그 역할).
  지금 안 만들어도 잃는 자료가 없다.

만들 때의 설계 스케치:
  clientInfo["이름|지점"].places = [{ sb, name, zip, addr, addr2, taxEmail, contacts:[...] }]
  - 업체 식별자(이름+지점)는 건드리지 않는다. 상세(clientInfo) 안에만 들어가므로 위험도 낮음.
  - 입력 UI 는 기존 담당자 줄 추가/삭제 패턴(_clxContactRow)을 그대로 재사용.
  - 기존 단일 칸(subBiz/addr/taxEmail)은 "대표 사업장" 값으로 남기고, places 가 있으면 그쪽 우선.
  - 초기값은 _fxVsbList 로 계산서 이력에서 종사업장번호를 뽑아 줄을 만들어 주면 입력 부담이 준다.
