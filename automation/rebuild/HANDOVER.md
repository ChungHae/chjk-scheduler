### 6.1 배경/목적
- 기존 회계>입출금 탭은 외부 Streamlit 앱(chjk-manage.streamlit.app, repo ChungHae/chjk-manage)
  에 의존: 엑셀 업로드→입금자명 문자열 매칭→거래처별 상태(완납/진행/미수/장기미수) 엑셀 누적본.
- 문제: 미수 산정이 건별 문자열 매칭 기반이라 구조적 허점(부분입금·묶음입금·선수금).
- 실제 거래 입력은 상용 ERP에서 계속함(이중 입력 금지). 이 시스템은 자료(계산서·은행) 기반 조회용.
  단 미수 산정은 ERP 방식으로: **잔액 = 기초이월 + 매출계산서 누계 − 입금·어음 누계 ± 조정**.

- 회계 아래 새 탭 "매입매출" 신설(기존 입출금·카드매출 유지, 검증 후 기존 삭제 예정).

  거래처 클릭시 페이지 내 원장(계산서/입금/어음/조정 시간순+잔액 흐름) 즉시 확인 + 엑셀 다운로드
  ② 매입·매출 집계 — 계산서 기준 월별/거래처별(매입은 집계까지만) ③ 자료 업로드 — 자동판별·중복제거,

  번호가 없는 게 아니다. 기초이월·조정은 계산서 없이 미수를 만들므로 번호 없는 배정을 완전히 막으면 안 된다
  (_fxHasLedgerBasis 로 판정 후 확인창).
- 배정 주의(r154): 입금 배정은 반드시 등록된 거래처(_fxClientOpts)로 확정된 뒤에만 이뤄진다.
  새 배정 경로를 만들면 vendor 를 바꾸기 "전" 에 _fxAsgStamp(e, bat) 을 호출해야 되돌리기가 동작한다.
- 성능 주의(r152): fx 블롭 6개는 동시 요청된다. _fbFetch 를 쓰는 새 코드는 동시 호출 가능해야 함.
- 성능 주의(r151 이후): 원장은 캐시된다. fx 자료를 바꾸는 새 코드는 반드시 _fxSave() 또는 _fxSaveBig() 를
  거칠 것(둘 다 _fxCacheBump++ 로 캐시를 무효화). 이 둘을 안 거치고 배열만 제자리 수정하면 화면이
  옛 수치를 그대로 보여줄 수 있음. _fxLedgers() 반환 배열은 공유 참조이므로 정렬·변형 전 slice() 할 것.
- 하니스 주의: fbConnect 안정화 3.5초 대기, 신규 localStorage에서 재고 첫 렌더가 invAdjust 리셋,
  input[data-...] 선택자는 체크박스도 잡힘([type="text"] 추가), 미수 배너는 KST 타임존 컨텍스트로 테스트.
- 사용자 대화 스타일: 한국어, 반말 지시. 완료 보고는 간결히 + "미배포/배포됨" 상태 명시.
